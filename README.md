# LegspCpd 友链数据源

本站（[blog.legspcpd.top](https://blog.legspcpd.top/)）的友链列表数据源。

- **每条友链一个文件**，放在 `data/friends/` 下
- 合并后由 Action 自动聚合为仓库根目录的 `friends.json`，站点构建时读取它
- 提交 PR 后，Action 会校验格式并**尝试检测你站点上是否已添加本站链接**，把结果贴在评论里

> 从本站**友链页**点「打开友链仓库，添加友链」按钮也能直接到这里：<https://blog.legspcpd.top/friends/>

## 怎么提交友链

两种方式，任选其一。

### 方式一：一键申请（推荐）

1. 打开本站友链页：<https://blog.legspcpd.top/friends/>
2. 点页面**右上角**的「申请友链」按钮
3. 填写：站点名、站点链接、头像链接（可选）、友链页链接（可选）、简介（最多 100 字）
4. 勾选「我已在友链页面添加本站链接」，点提交
5. 页面会直接给出生成的 PR 链接；机器人随后自动校验并在 PR 里留言，维护者合并后就出现在列表里

弹窗里会**实时预检**：字段格式、简介字数、站点能否打开、头像能否加载。

**没填的字段会自动补全**：填好站点链接后，站点名、头像、简介会尝试从你的站点抓取填入
（友链页链接也会顺带找一下地址里带 `friends` 的页面）；你已经填过的字段不会被覆盖。

**提交限流**：为防止刷单，同一来源每小时最多提交 2 次。
「有没有放本站链接」这一项浏览器跨域查不了，由机器人收到 PR 后检查。

顺便说一下：**文件名忘了写 `.json` 也没关系** —— 机器人检测到会自动补上后缀，再重新检查一遍，并在 PR 里告诉你。

### 方式二：手动提 PR（Fork 流程）

1. **先 Fork 本仓库**（点右上角 Fork，或直接打开 <https://github.com/LegspCpd/friends/fork>）
2. 在**你 Fork 出来的那份仓库**里，于 `data/friends/` 下新建一个 JSON 文件，内容按下面的格式填
3. 从你的仓库向本仓库**提交 Pull Request**
4. Action 会自动在你的 PR 里留言：校验字段 + 访问你填写的页面检查回链；维护者合并后就会出现在本站友链页

**文件名规则**：用你站点的短名，只含字母、数字、`-`、`_`、`.`，例如 `your-blog.json`、`2x-nz.json`。文件名只用于区分条目，展示的是文件里的 `name` 字段。

**想少点几下？** 在**你 Fork 的仓库**里，把下面链接的 `<你的 GitHub 用户名>` 换成你的用户名，即可直达「新建文件」页面（路径已填好）：

```
https://github.com/<你的 GitHub 用户名>/friends/new/main?filename=data/friends/your-blog.json
```

## 字段说明

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | ✅ | 站点名，非空，最多 60 字 |
| `avatar` | ✅ | 头像 URL；没有就填 `null`，页面会用占位图 |
| `description` | ➖ | 简介，最多 100 字 |
| `url` | ✅ | 你的站点地址，必须是 `http://` 或 `https://` 开头 |
| `backlink` | ➖ | **你放置本站链接的那个页面**。填了它，检查器会直接去看这一页，成功率更高 |
| `tags` | ➖ | 标签数组，最多 5 个、每个最多 20 字 |

## 常见校验失败原因

- `url` / `avatar` / `backlink` 不是 `http(s)://` 开头（例如写成了 `javascript:` 或漏了协议头）
- 文件名或内容里带了不在上表中的字段 —— 多余字段会被拒绝，防止意外注入
- `url` 与已有友链重复
- JSON 语法错误（最常见的：末尾多了一个逗号、引号没配对）

**任何一个文件不合格都会让构建整体失败** —— 这是刻意的：宁可让构建红掉，也不产出一份悄悄少了人的友链列表。

## 关于回链检查

Action 会访问**你在 JSON 里填写的那个页面**（填了 `backlink` 就用它，否则用 `url`），检查里面有没有指向本站的链接。

以下域名**任意一个**都算数（带不带结尾斜杠、http/https 都可以）：

- `https://blog.legspcpd.top/`
- `https://www.legspcpd.top/`
- `https://legspcpd.top/`

也就是说：你在自己站点上放的是哪个域名，就按哪个域名判定，不必三个都放。

## 检查结果与标签

Action 会在你的 PR 下留一条评论，并给 PR 打上标签。**一项检查一个标签**，通过/不通过成对出现，方便一眼看出卡在哪一项：

| 检查项 | 通过 | 不通过 | 说明 |
| --- | --- | --- | --- |
| 站点 | `网站可达` | `网站不可达` | 你填的站点地址能否打开 |
| 头像 | `头像可达` | `头像不可达` | 头像地址能否加载（没填头像则不出现这两个标签） |
| 双向链接 | `双向链接验证` | `未找到回链` | 你填的那个页面里有没有指向本站的链接 |
| 汇总 | `URL 全部可达` | `URL 有不可达` | 站点与头像是否都可达 |
| 特殊 | `回链检查受限` | — | 对方站点有反爬/人机验证，抓不到页面，**不算你没加** |
| 类型 | `友链` | — | 所有友链 PR 都会带上 |

此外还会有一个 `link-check:` 开头的历史标签（旧版方案留下的），可以忽略。

## 关于死链巡检

每周一会自动巡检一次所有友链（Actions 里也能手动触发：`weekly-link-check` → Run workflow）。

**只有以下情况才会被判定为死链并移除**：

- 域名解析失败、连不上、超时
- 返回 **404 / 410**

**以下情况一律保留**（可能只是对方反爬或临时故障）：403、429、5xx 等其它状态码。

被移除的友链会出现在本站友链页下方的「**已移除的友链**」区块里，标注站点名、原地址、原因与日期。

> 如果你的网站在其中：**站点恢复后请重新提交申请**即可（点友链页右上角的「申请友链」，或按上面的方式二手动提 PR）。

## 撤销友链

把你的 JSON 文件移到 `data/rejected/`，或直接提 PR 删除该文件。
